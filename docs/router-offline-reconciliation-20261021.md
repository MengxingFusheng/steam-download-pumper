# 2026-10-21 离线恢复与路由器开机核验

计量恢复时增加系统开机时长与累计线路流量核验，防止在路由器重启、线路明确离线时仍按历史上传均速或满带宽增加上传量。

## 处理规则

- 同时读取并持久化 `hrSystemUptime` 和 `sysUpTime`。前者表示系统初始化后的时间，后者表示管理服务初始化后的时间，SNMP 服务重启不能独立证明路由器断电。参考 [RFC 2790](https://www.rfc-editor.org/rfc/rfc2790.html) 和 [RFC 3418](https://www.rfc-editor.org/rfc/rfc3418.html)。
- 节点或采集器离线、路由器持续运行且线路计数连续时，用累计上传、下载差额恢复真实流量。
- 将 uptime 增量与两次观测间隔对照，识别恢复后 uptime 仍高于旧值的重启，同时处理 TimeTicks 32 位回绕和采样误差。
- 确认系统重启时，保存 `router_reboots` 证据记录。对上次线路基线到本次开机之间不可对账的缺口，不追加估算上传或未知上传预算，仍保留缺口标记；核验本次开机后的线路累计上传、下载量，并按物理上限校验。
- uptime 只能证明发生了重启，不能还原确切断电时刻。重启前不可对账的时段不会被声明为完整、实测零流量。
- 线路明确 down 时，读取仍有效的累计差额，保留离线前已发生的真实流量，不凭历史均速补记上传。线路计数重置且当前明确 down 时同样不补上传。
- 无有效系统开机证据时，不将普通 SNMP 采集失败强行判为路由器离线。未知状态继续保留，计数可连续恢复时清除暂存未知预算。
- 路由器重启后线路尚未出现时不启动该线路下载；其后恢复时按持久化重启证据对账。缺失第一组计数的线路同样保留初始缺口时间。
- 修正沿用代理的历史图表重导机制；配置中的带宽、倍数、6 小时每日下载下限和既有历史补记规则不变。

## 验证与部署

五个路由器均已实际确认支持系统开机时长查询。部署前在线备份两份 SQLite、配置和账号 CSV，部署后核对节点身份、全部 Python 文件哈希、账号映射、配置和其他容器状态。版本为 `fleet-pumper:router-reconcile-20261021`。

针对恢复逻辑的测试覆盖系统持续运行、管理服务独立重启、系统重启后 uptime 大于旧值、32 位回绕、节点进程重启、线路延迟恢复、明确 down、不可验证计数、跨午夜分配、重复恢复、历史图表修正及缺失线路不进入调度。

Python 全量 399 项：398 通过、1 项跳过；生产同版本 Python 3.13 下 104 项相关测试通过。没有为验证而重启真实路由器，重启与断流边界通过隔离测试验证。

本次不根据缺乏开机证据的旧未知记录推断断电时间，也不批量删除旧实测上传。新开机观测及重启证据会持久化，供之后的离线恢复核验使用。
